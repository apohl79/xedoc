Set up trusted HTTPS

Do this once on each device you use to access Xedoc. Hosts enrolled by this coordinator will use the same private certificate authority (CA).

  1. Verify the CA

    Before installing anything, compare the SHA-256 fingerprint below with the coordinator administrator using a separate trusted channel, such as a call or in person. Stop if it does not match or you cannot verify it.

    Loading…

  2. Download the public CA

    For Windows, macOS, Linux, Android, or Firefox: Download the Xedoc CA certificate.

    For iPhone or iPad: Download the Apple installation profile. It contains only the public CA certificate.

    Install a download only after verifying its fingerprint. Never download or share ca-key.pem; it is the private signing key.

  3. Install and trust it

    Choose your device or browser for the steps:

    Windows · Chrome / Edge

    Open the downloaded certificate → Install Certificate → Current User → Place all certificates in the following store → Trusted Root Certification Authorities → Finish. Restart the browser.

    macOS · Safari / Chrome

    Open the certificate in Keychain Access and add it to the login keychain. Open the certificate → Trust → When using this certificate: Always Trust. Confirm with your password, then restart the browser.

    Linux · Chrome

    Open chrome://certificate-manager → Custom → Installed by you. Import the downloaded CA as a trusted certificate.

    Firefox

    Settings → Privacy & Security → Certificates → View Certificates → Authorities → Import. Select the CA and trust it to identify websites.

    iPhone / iPad

    In Safari, download the Apple installation profile above. Open Settings → Profile Downloaded → Install and follow the prompts. Then go to Settings → General → About → Certificate Trust Settings and enable full trust for the Xedoc CA. A downloaded profile is not fully trusted for websites until you enable this setting.

    Android

    Settings → Security → Encryption & credentials → Install a certificate → CA certificate. Select the downloaded certificate. Menu names vary by device; some apps may not use user-installed CAs.

  4. Reconnect to Xedoc

    Reload the Xedoc page. The browser should now accept HTTPS certificates issued by this CA for enrolled hosts.

Before the CA is trusted, your browser may warn that this connection is not private. Do not bypass that warning blindly. If you cannot verify this page’s fingerprint or your browser will not let you reach it, ask the coordinator administrator for the public CA file and its fingerprint through a trusted channel. Verify the fingerprint before installing the file.

Trust this CA only if you control or trust its administrator. A trusted CA can issue certificates for websites. Never install a CA whose fingerprint you have not verified.
